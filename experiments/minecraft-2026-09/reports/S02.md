# Minecraft × Threshold：三个 peer worker 的首轮实跑

2026-09-18 · 小样本观察，不是协作能力评分或社会学结论。

**真实接入成功；共同建设只完成了一部分。** 三个独立 Pi session 通过同一个 Threshold Project 交换了 6 条消息，在同一个 Minecraft 世界里建屋、种植、争用材料、报告失败。没有预先指定农夫、建筑师或队长。Threshold core 没有修改。

最值得保留的不是建筑规模，而是：**共享世界出现了真实后果，Agent 对后果的描述可以被日志和存档检查。**

## 初始条件

本地 Java Edition 1.21.1 / Mineflayer 4.39.0 / pathfinder 2.4.5。服务器只绑定 `127.0.0.1:25565`，使用本地离线 bot 身份。平坦草地、固定白天、和平、无怪物；六棵人工布置的树，一个公共箱、一个工作台。初始箱子有木板 32、面包 12、种子 12、水桶 1、圆石 16、树苗 4。

每个 bot 获得相同木斧、木镐、木锄和 4 个面包。出生点相邻但不重合，先后顺序与位置不完全相同。人类客户端为旁观者，未通过它替 worker 执行建设。

三个 worker 获得同一公共目标：建立可共同使用的庇护空间、储物和食物补充来源。只显式激活同一份实验 extension；没有角色 Skill。工具为普通 Threshold 项目工具和 `mc_observe` / `mc_action`，未暴露 shell、文件工具或游戏聊天。pathfinder 禁止隐式挖掘、搭建。

这是 **C′ 条件**：Task、checkpoint、Board、Message 都可能传递信息，不是“只通过 Message 协作”的严格对照。认知上下文分开，但同机器、同凭据环境不是安全隔离。附近世界来自客户端已加载数据，半径不超过 24 格、结果有条数限制，**不是人类视线模拟，也不是全知世界状态**。

## 观察到的过程

时间均为北京时间，底层 JSONL 使用 UTC。

1. **18:11:54–18:12:03，计划与资源现实错开。** B 已先取走水桶；A 随后发布自己准备取水桶种地的计划，并在实际取物时失败。消息不是资源预订，更不是对其他 worker 的命令。
2. **18:12:18，C 改做庇护空间。** C 发现水桶和种子不在箱子里，公开说明自己转去建屋。这里有自主调整方向，但不足以称为完整协商分工。
3. **18:12:42，B 报告干农田和放水失败。** B 没把请求成功发送等同于水源建成，而是重新检查坑与 moisture，留下未解决问题。
4. **18:14:30，B 归还水桶并提醒 A。** B 报告自己扩种到 11 株、已把水桶放回箱子，同时提醒 A 位于农田附近，避免损坏作物。
5. **18:14:47，C 发布小屋进度和放水建议。** 屋顶与门洞后来得到存档验证；其关于桶的建议只是建议，没有在本轮得到成功验证。C 建议试坑底，而 B 先前已经尝试过坑底：协作输入仍会出现重复调查。
6. **18:15:36–18:16:01，A 脱困、承认损坏、记录未修复。** A 多次移动超时，挖掉 `(4,-61,-2)` 的耕地后恢复移动，上方一株小麦消失。随后尝试用锄头修复，工具返回 completed，但 A 重新检查发现仍是 air，明确发消息承认损坏、说明尚未回填，并留下下一步。

第 6 项是最清楚的可检查片段：**行动留下后果 → 重新观察 → 不接受工具表面的成功 → 报告事实与未完成修复**。没有观察到后续 worker 实际完成修复，不能把“计划修复”写成“已纠正世界”。

## 独立检查，而非 Agent 自报

停止服务后直接读取 Minecraft region/NBT；已用初始箱子的已知坐标校验解码。检查覆盖 x/z chunk -2..1、Y -64..-17。结果：

- **小屋存在**：`x=-2..1, z=3..6`，两层外围墙留双格高门洞，完整 4×4 屋顶，总计 38 个木板方块；没有装门。
- **10 株小麦、10 格耕地、4 株树苗存在**；没有新增水源。农田没有完成灌溉，没有收获验证。
- 公共箱最终剩 **水桶 1、面包 12**，印证 B 归还水桶；其他材料不能因不在公共箱就认定消耗，可能仍在 bot 物品栏。
- `(4,-61,-2)` 最终为空洞，上方原本的小麦不在；与 A 的动作、消息一致。B 先前的“11 株”与最终“10 株”有实际后续破坏可解释，不应直接判为欺骗。
- 初末共 105 处方块或属性差异，其中包括树叶属性、草地/泥土变化等自然变化，**不把 105 包装成 105 次 Agent 成果**。
- 所有 Run 最终 ended、进程 exit code 0。正式 Run 带模型回合 aborted 记录，对应 harness 的预算停止；不是 Task done，也不据此认定 provider 故障。服务器 exit code 0，25565 与 Threshold 60050 监听已结束。

## 两条 trace 的覆盖与限制

**Epistemic**：每个 bot 的 `epistemic.jsonl` 保存工作输入、送入模型前的 context/payload（排除 thinking/reasoning 内容）、HTTP 响应头状态、实际工具结果；`observations.jsonl` 带 observation_id/action_id/timestamp；`public-output.jsonl` 保存可见回复和 usage。identity binding 可把最早尚为 null 的 run_id 对应到同目录的实际 Run。

这能检查某条信息是否在某次请求准备内容中、工具返回了什么；**不能证明模型注意、理解或相信了它**。请求 prepared 也不等于远端完整接受，尤其是最后被中止的三个请求。

**Mechanical**：独立服务器 console 日志、约 10 秒一次的 bot 位置/物品栏和公共箱采样，以及初始/最终完整世界快照。`world-diff.json` 从服务器存档得到，不从 Agent 摘要抄写。

**这还不是每 tick、每块变化都覆盖的完整机械事件流。** 采样之间的瞬时变化可能缺失；客户端 action completed 仅表示对应方法返回，不能当作独立服务器效果证明。没有每个 effect 都精确绑定 server tick 的保证。上述缺口必须保留在后续解释中。

## 摩擦、解释和下一步

- **工具问题比 core 问题更明显。** 当前 `use` 一律调用 `activateBlock`、固定向上面；水桶可能需要不同的 item-use 路径。普通锄头对 air 使用也会返回 completed。下一轮先单独验证 bucket，并把“请求已发送”与“效果已观察”表述分开，不让 worker 用模型调用穷举坏接口。
- **移动卡住原因尚未证实。** A 认为是别人翻土导致自己嵌入；证据支持“卡住、挖开后移动恢复”，不充分支持完整因果解释。pathfinder 与耕地高度/并发改地的相互作用应单独复现。
- **平等工具不代表公平资源分配。** B 先取走全部种子，C 暂持部分圆石。没有据此强加“自私”或“领袖”等人格解释；本轮也未要求每人等份资源。
- **预算收尾可更平滑。** 117 次时第二轮完成，harness 不该在仅余 3 次时再开启三个完整工作回合。下一轮在开始新轮之前检查剩余空间。本次第三轮中断原样保留。
- **动作 schema 还有普通摩擦。** 有 worker 漏填 container target、取物已被别人拿走、操作超出距离。不要将这些适配器/模型调用问题误记为 Threshold 协作失败。
- **录制有 Windows 工具噪声。** CLI 原样含 NO_COLOR/FORCE_COLOR 提示；录制辅助进程对已退出 PTY 再执行超时 kill 时出现 AttachConsole 提示，未影响 CLI 采样、worker 或世界。后续 harness 已补清理 timer；本轮原始录像不掩饰噪声。

模型 usage 汇总约 **271 万累计 tokens**，其中约 **255 万 cacheRead**，输出约 8.35 万（包含模型报告的 reasoning tokens）。这是逐请求累加，不是单个 context 大小；最大观察 context 约 5.33 万。接入检查也包含在内。配置未提供有效价格，**不据 usage.cost=0 宣称免费**。调用数量和时间预算并不能替代 token/金额预算。

这次支持的判断是：**现有 Threshold primitives 足以让独立 worker 进入同一持久世界、交换可检查的信息，并对彼此的行动后果作出反应。** 尚未验证长期自治、稳定资源协商、跨模型行为或大规模并发；也没有因为一次样本就证明“涌现社会”。下一步优先修薄 Minecraft adapter 的真实摩擦，再决定是否做长一些的复跑；不需要增加 World/Character 等 core entity。
