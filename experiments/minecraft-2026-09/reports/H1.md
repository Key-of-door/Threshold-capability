# 历史通道消融：没有项目叙述，工作仍能接续；但这不等于叙述无用

2026-09-19（北京时间）｜一次探索性配对，不是统计验证

**本次观察支持一个有限结论：在熟悉 Minecraft 规则、共同目标明确、世界可重新检查、每个 worker 保留自身当前会话的条件下，显式 Message/checkpoint 历史不是这一次短期工作接续的必要条件。** 消融组仍使用已有设施、形成跨 worker 材料接续并留下真实成果；对照组也有消息参与的接续。两组都存在重复投入、失败和不准确解释，不能据此宣布哪一组更优，更不能推论 Agent 不需要通信。

## 实际做了什么

从上一轮资源组结束存档与 SQLite Project 分出两个独立副本，随机分配条件后先跑 `r17`（历史关闭），再跑 `r42`（历史可用）。每组3个全新 Pi session，沿用原模型、世界动作、窗口串行机制、epistemic/mechanical hooks、快照和 CLI 录制设施，无人工分工或纠错。

两组服务器真正开跑前再次核对：扫描范围内方块和容器相同，三位 bot 的存档相同，gameTime 同为70524。相对于源快照，两次启动都只推进1 tick，未发现方块/容器变化。没有加资源或修地形。

两组共同使用简短目标与中性继续提示，取消强制保存 checkpoint。历史可用组可自选 read_messages/send_message/save_checkpoint，read_work 还提供最新 checkpoint；消融组只开放 read_work/mc_observe/mc_action。两组都关闭 board、Task 状态写入、旧 Run 检查和通用 shell/files，避免替代叙述通道。旧历史仍在各自数据库中，CLI观察者可见；消融组模型不可见。

没有修改 Threshold core。实验侧以小型 API view 和 workerFactory 包装去掉自动注入的代码任务／checkpoint指令；Minecraft extension 仅在两组相同地删去两处“必须保存 checkpoint”文字，动作和记录 hooks 未改。实际加载的路径/SHA、原始及替换后的启动提示均保留。不是 OS 安全隔离，也不是双盲实验。

## 已核对的接续与错误

### 消融组：误认施工时间，材料却接上了

B把 z=-6、x=1/2/3 的三段围栏解释为其他 bot 正在搭建。初始存档证明它们早已存在。18:20:29Z，B仍据此把9段新栅栏存入公共箱，使库存6→15；18:25–18:26Z，C分批取出并放置9段，库存回到6，世界围栏3→12。

这里确有共享库存支持的工作接续，同时存在错误的时间归因。同类物品已混堆，不能逐根说“这9根都是B的”；但原库存只有6，本次取用的9根至少有3根依赖新增供给。见[动作、容器结果与初始围栏位置](r17/selected-episodes.json)。

### 消融组：换工具成功，解释仍越过了证据

A早期挖石没有获得圆石。中途存档显示当时选中的槽位为空，动作记录也没有装备石镐；后来它自行取出公共铁镐，18:30:24Z明确 equip，随后累计存入13圆石，并制作石斧、石锄。

A最后却总结成“铁镐才行，石镐不行”。本次并没有相应的石镐失败对照，不能推出这个结论。世界30块石头最终全部消失，已核对新圆石入库13；不能把采掉的30块全算成有效产出。有限资源损失与工具改进同时发生。换一种操作后获得结果，并不保证因果解释也被正确更新。

### 对照组：消息与现场观察共同进入接续

C将3原木放入公共熔炉，并在消息59说明。A于18:39:44Z读到消息56–60，之后观察熔炉，18:40:07Z取出4木炭（含原先已有的1份产物），入库并追加5原木。C后来又观察到炉内变化。C新建燃料箱后，A也实际从该箱取燃料。

这与消息提供线索、现场复查再行动相容；不能从一次时间顺序证明消息不可替代，也不能把它称为“纯世界状态驱动”。完整输入索引修正了观察者早期只看监控概要时的判断。见[消息暴露与熔炉动作链](r42/selected-episodes.json)。

### 对照组：旧时间可以制造新的误判

B写“(2,-4)自16:24一直停在age6”，后来称“两小时”，并据此修枝排查。墙钟时间包含停机与冻结，不能直接当作世界生长时间。本轮真实世界只推进约16分钟。B之后仍保留“修枝后要继续观察”的不确定性，并没有声称已证实原因。

另一个重复投入候选是石剑：A已把石剑放入主箱，B仍提出把木剑升级为石剑并采石。B第一次实际读到主箱有石剑是在18:48:11Z，晚于该计划；最终没有第二把石剑。因此这是过时库存认识下的重复尝试，不能写成“看见石剑却故意重复制造”。

## 世界确实改变，但没有一个总分

| 最终核对的变化 | 历史关闭 | 历史可用 |
|---|---|---|
| 已放围栏 | 3→12 | 3→10 |
| 小麦植株 / 耕地 | 12→15 / 33→34 | 12→12 / 33→32 |
| 公共箱小麦 | 0→2 | 仍0 |
| 已放木板 / 箱子 | 70→82 / 仍2 | 仍70 / 2→4 |
| 剩余地表石头 | 30→0 | 30→19 |
| 新存入公共工具 | 石斧、石锄 | 铁铲、木剑、石剑 |

面包增加主要是个人库存转入公共箱，不是新生产。新工具不等于已获得后续效益；植株数量会掩盖旧苗收割/损失和补种；树木增长包含自然变化。火把两组分别放23/20支，但用途是否必要不能用数量判断。没有把所有方块差异、所有动作或库存增长都算成有用工作。

消融组三人的首次世界动作发生在开跑后11.5–16.1秒；对照组15.2–47.2秒。**这是首次动作，不是首次有用成果，更不是冷启动质量评分。** 本次没有观察到消融导致明显的入场停滞；两组很快进入操作。但消融组错误动作更多，且存在石头损失，因此也不能宣称成本更低或协作更好。

## 不能忽略的限制

- 一对样本、一个模型家族、每组约16分钟；不支持长期、大规模或陌生领域结论。当前Run内的自身对话一直保留，没有测试再次换一批worker后的多代接手。
- 消融同时移除历史bootstrap、在线消息与checkpoint读写，是组合干预；不能分离每一项价值。写给用户的普通回复仍然存在，也可能帮助自身整理思路。
- 共同精简Task没有重述“和平、固定白天”；原 mc_observe 也不返回世界时钟、难度、day-cycle或光照读数。两组都有夜间防怪/补光叙述。它们可能是在缺少环境信息时使用一般Minecraft知识，不能把这些行为单独归因于历史通道。下一轮若补静态规则/时钟，需要作为新条件重新配对，本轮没有中途补。
- 控制了相同起点与启动ticks，不能控制模型采样和之后的自然生长；最后时长相差约6秒。没有对“有用”做盲评或统计检验，也不制造一个综合分数。
- r17 C曾请求合成木棍，返回背包却出现4原木，随后服务器Inventory也确有4原木。registry中848仍是stick，并不是它解释的oak_log。异常日志已保留；物品来源和窗口/交易根因未确立，不能完全归为模型幻觉，也不能把C的映射诊断当成事实。本轮不改原设施，相关片段不用于强因果结论。
- 消融组B也自行产生了“世界没有石矿”的泛化，虽同期A在挖地表石头。相似错误可以独立重新生成；不能看到相同说法就认定是历史传播。两组出现的局部更正也不等于全局共同知识收敛。

## 当前判断

本次最清楚的结果是：**去掉显式项目历史，并没有让这三个fresh worker失去进入基地、利用已有物资和接续他人成果的能力。** 共享现实足以支撑这一次有限的工作连续性。但它也没有自动提供准确归因、资源保护、高效分工或正确的因果解释。

历史可用时，消息确实成为部分worker的输入，并与真实接续同时出现；另外两位没有持续读消息。历史既可能减少调查，也可能带入过时假设和错误时间推断。本次不支持“Message没用”，也没有建立其平均收益。没有需要新增Threshold core primitive的阻断。
