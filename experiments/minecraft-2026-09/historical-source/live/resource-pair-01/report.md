# 资源分叉实验：新行动出现了，共识没有自动出现

2026-09-18 深夜至 09-19 凌晨 · 一次探索性配对实验

**结论：新增矿点确实打开了新的跨 worker 加工链，但没有证据表明这一次使整体协作更有效或认知更一致。** 两组都完成了有实际后果的工作；新消息均未被其他 worker 再次读取。没有改 Threshold core。

## 条件与边界

从 session-05 的同一份结束存档和 Project 数据库分出 control / intervention，分别运行三位全新 Pi worker，各12段。两组不共享本轮对话、新消息或 checkpoint，保留同样的旧历史、目标、初始背包与位置。不指定职业、负责人，不要求通信或一致。

资源组增加两处混合露头，共48石头、4煤矿、6铁矿。准备后的数据库、玩家数据、容器内容相同；实际开跑前，在可操作区域的核对范围（x/z -64..63，y -64..-17）内，方块差异恰好58处，均为上述介入。两组起始 gameTime 都为53205。等待前台录像时冻结 tick，开跑才恢复。

两组**共同**使用修复后的同-bot物品窗口串行操作、新增的薄熔炉读写接口，以及相同的开场材料搜索提示。因此与上一轮相比不止资源发生变化；只有本次两组之间可比较资源条件。没有补充角色专属工具、食物或熔炉，没有途中补矿、纠正 Agent 或改 prompt。配置为 DeepSeek Flash，1M上下文/384K输出上限，沿用每组600模型回合/30分钟等共享硬预算。实际配置与源码指纹见 [conditions.json](conditions.json)。

## 三段值得回看的过程

### 1. 对照组：实际接续成功，归因仍然错误

C 在16:06:23Z观察到 (3,-60,-4) 的小麦 age7，随后收割。B 之后拾到 wheat1 / seeds3，用种子补种三格，并把麦粒入公共箱。C 在该时段没有取得这些麦粒或种子。这条动作、背包和存档链支持“C的工作被B继续使用”，但没有逐个掉落物 UUID 的完整溯源。

B 的最终摘要却仍写成“(3,-4) 已被 MicaA 收割”。实际收割 action_id 为 `call_00_26x4mAGqXgQjodbVpIeZ5321`，来源是 C；A 早已停止行动。**产品成果能够接续，并不意味着对成果来源的解释已经收敛。** 这也不能叫作所有错误都会自动被纠正。

对照组还自行出现了清树叶取苹果、围栏、堆肥尝试，以及原木→木炭→火把。B 在消耗一个面包后判断堆肥不划算并停止。它们没有被指定去做这些事情。最终有24段围栏、1道栅栏门、1个堆肥桶、1个新增箱子；小麦植株12→15，耕地35→32。围栏并不自动证明完整防护，计数也不能替代具体地形检查。

### 2. 资源组：共享熔炉形成了真实材料链

按实际记录（UTC）：

- 16:13:36，A 放入粗铁1；随后 A、C 各放煤1。
- 16:13:39，C 再放粗铁2，共同炉中原料达到3。
- 16:14:10，A 取出铁锭3。
- 16:14:34，A 合成铁镐；16:14:38 把它存入公共箱。
- C 另采、冶炼并取回最后一块铁锭。B 后来使用已有炉与燃料处理原木，A继续加工木炭。

这超过了“三个人各自做出一个东西”：一个人的投入进入了另一个人的加工结果。细节见 [material-chain.json](intervention/material-chain.json)。

但 C 曾把三份原料消失描述为“不确定被A取走了原料还是成品”，并没有共享全知过程。铁镐存入后无人领取；C 后来建成的第二座炉子没有加工操作。**形成共享资产，不等于该资产已带来后续效益。** 铁煤矿被采空，仍有30块石头；最终只有四块铁锭的产物得到核对（三块用于铁镐，一块在C背包）。B 怀疑自己用错镐导致矿物无掉落，这一解释与记录相容，仍与直接可见的产物数量分开记。

### 3. 更多资源并未消除原有摩擦

资源组大量时间仍用于门口、石柱和农田边的寻路。C 拆除了部分石柱，也留下了探矿坑；A 的消息把另一处失败归因于寻路器，并对踩苗作出推断。这些因果解释不是服务端自动确认的事实。

最终资源组没有小麦入库，只有3段已放置围栏及6段存箱围栏；植株仍12株，但这掩盖了旧苗消失、新苗补种，不能理解成没有损失。对照组则跑通了收割补种。单次差异不能证明“加资源降低效率”：模型采样、随机生长、行走路线、踩踏以及约10秒的时长差都可能有关。

## Message、限制与判断

两个分支里，所有 worker 都只在开场读取旧消息（最大ID47），之后没有再读新增消息。没有 read_project_board 调用，read_task也各只一次。新消息保存了求助、警告和更正，却没有构成本轮可确认的对话反馈链。**这里主要观察到的是共享环境与公共物资上的接续，不能包装成消息驱动的协商或组织形成。**

这不是盲测：Pi系统提示含工作目录，目录名包含 control/intervention；先跑对照再跑资源，只有一对样本、同一模型家族、短时间窗口。信息边界仍是 prompt/workflow 层，不是安全隔离。双trace保存的是可见输入和机械记录，没有隐藏推理，也没有逐帧、逐物品的全知因果记录。熔炉即时打开时 progress/fuelRemaining 会返回null，槽位与成品检查有效，但不能把null当作零进度。窗口修复先在独立服务器复现验证，两组使用相同代码；没有中途修饰结果。

当前更稳妥的判断是：**资源介入能扩展可做的事，也能形成跨 worker 的材料依赖；重新观察使局部接续成为可能，但不会自动形成共同知识、正确归因或高效分工。** 不需要据此增加 Threshold core 概念。若继续研究，应先挑一个具体信息/行动缺口，而不是把所有摩擦同时修掉再宣称原因已找到。
