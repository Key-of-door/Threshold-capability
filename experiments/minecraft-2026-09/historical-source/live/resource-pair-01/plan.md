# Minecraft × Threshold：资源条件分叉

工作参考，现场如需改变条件应先记录，不把结果作为预定结论。

## 要问的问题
增加可用原材料以后，是否出现可观察的跨 worker 贡献依赖？仅总产出增加不等于协作增强。资源不足是待检验解释；旧消息未再阅读、陈旧信念、工具摩擦也可能重要。本轮不顺便修消息行为。

## 分叉
共同来源为 session-05 的 final 世界及停止后的 Project SQLite。control 和 intervention 有独立数据库、世界目录、全新 Pi sessions 与 Git worktrees。相同历史 ID 是分叉来源一致的结果，后续新增 Run/Message 独立。Project 的 canonical Git root 沿用 session-02/repo；本实验的产品是外部世界，工具不暴露 shell/files。原世界、旧报告不改。

两组唯一预设的世界差异是两个浅层混合露头，总计石头48、煤矿4、铁矿6。不补食物、工具、熔炉，不移动工人，不授予任何人所有权，不指派职业。位置与逐方块核对见 fork-manifest.json。共同准备时先启动原世界副本并冻结 tick，再依次取得无资源/有资源快照。此共同准备可能比原 final 存档多推进少量 tick，但两组基线一致。

## 共同接口与提示变化
不能把本轮与上一轮当成只改变资源的严格对照。两组都加入熔炉原料/燃料/成品操作、熔炉读取及同一 bot 窗口串行处理；通用 interact 不能绕过这条窗口路径。没有生产宏或协作协议。两组开场均要求普通材料搜索（stone 单独查询，coal_ore/iron_ore 另查），不提供矿点坐标、不要求采矿。这个共同的注意力提示也应在报告中披露。

保留原 Task 与中性继续提示，三个平等 worker，各最多12段；每组硬上限600模型回合/30分钟，具体 token 上限见 conditions.json。采用同一 DeepSeek Flash、1M上下文/384K输出配置上限，不保证实际占用。先 control 后 intervention，单组一次；模型采样与执行顺序的差异未消除，不做统计显著性结论。

## 先验检查结果
- 独立测试服务器真实复现旧问题：面包箱和木头箱的同时读取都返回面包。服务端 NBT 表明物品实际不同。
- 新客户端使用队列后，三轮并发读取均返回各自正确内容。旧并发操作会留下迟到的窗口响应，因此测试修复时重连客户端，保留第一次失败记录。
- 真实生存链：木镐采石/煤、合成石镐、采铁矿、获得粗铁、燃煤冶炼、取得铁锭。通过服务端物品检查核对。空成品槽返回技术错误，之后仍可读箱子。
- 真正 pinned Pi 已加载 extension、工具 schema 和 active tool 列表，未调用模型。
- 准备脚本两次确认文字匹配错误均已停止服务器、保留日志；没有真实 worker 或模型调用。第三次成功，核对58处方块差异、相同玩家数据/容器/数据库。

## 运行与观察
等待用户录像期间冻结 tick，formal_start 才解除；启动前的少量 tick 仍须记录，不把段数当成相同世界时间。双方模型可见的 epistemic trace 与服务端 mechanical trace 独立保留，不向模型暴露观测者的全知数据。记录材料发现、采集、转移、冶炼、制作和使用链，区分直接交接、被动拾取、独立重复劳动与真正的后续利用；区分 Message 发出和实际被读取。

保留异常、争议和错误；不因为结果不精彩就在运行中改 prompt。最终报告同时说明工程效果和认知错误。没有开跑时不声称实验成功。
